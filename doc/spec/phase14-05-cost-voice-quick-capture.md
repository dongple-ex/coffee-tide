# Phase 14-05. 비용·음성 빠른 추가 구현

> 상위 로드맵: [`phase14-00-execution-roadmap.md`](./phase14-00-execution-roadmap.md)
> 선행 조건: Phase 14-04 Gate D 완료
> 완료 게이트: Gate E
> 상태: 업무·비용·짧은 음성 입력 핵심 구현 완료, 회의·오프라인 복구·모바일 검증 필요

---

## 1. 목표

기존 `빠른 업무 추가`를 업무·메모·비용을 수용하는 공통 빠른 추가 영역으로 확장한다. 음성은 별도 고립 기능이 아니라 각 입력 유형에서 사용할 수 있는 공통 입력 수단으로 제공한다.

### 핵심 사용자 흐름

```text
[업무] [메모·회의록] [비용] [더보기]       [마이크]

업무 + 음성   → 업무 문장 입력 → 사용자 확인 → 업무 저장
메모 + 음성   → 전사 → 요약/업무 후보 → 사용자 확인
비용 + 음성   → 금액/사용처/날짜 추출 → 사용자 확인 → 비용 저장
```

## 3. 빠른 추가 UI

### 3.1 데스크톱

```text
빠른 추가
[업무] [메모·회의록] [비용] [더보기]                 [마이크]
────────────────────────────────────────────────────────────
선택한 모드의 입력 폼
```

### 3.2 모바일

- `업무`, `메모·회의록`, `비용`까지만 기본 노출한다.
- 후속 입력 유형은 `더보기` 하단 시트에 둔다.
- 마이크는 아이콘 버튼으로 두고 접근성 이름과 툴팁을 제공한다.
- 모드 변경 시 작성 중인 내용이 있으면 버리지 않고 모드별 임시 초안으로 유지한다.
- 페이지 이탈·앱 전환 중 녹음 상태를 명확히 표시한다.

### 3.3 기존 기능 매핑

| 현재 기능 | 새 위치 | 호환 원칙 |
|---|---|---|
| 빠른 업무 입력 | `업무` | 입력·추가 결과 동일 |
| 메모/회의록 붙여넣기 | `메모·회의록` | 원문 추출·Drive 옵션 유지 |
| 파일 업로드 | `더보기 → 문서` | 기존 지원 형식·제한 유지 |
| AI 바리스타 입력 | AI 바리스타 탭 유지 | 빠른 추가와 합치지 않음 |

## 4. 비용 관리

### 4.1 입력 계약

사용자는 다음 두 방식으로 입력한다.

- 자연어: `오늘 고객 미팅 택시비 18,500원, 법인카드`
- 직접 폼: 금액, 통화, 사용처, 분류, 날짜, 결제수단

AI/규칙 추출 결과:

```ts
interface ExpenseDraft {
  amount?: string;
  currency: string;
  merchant?: string;
  category?: string;
  paymentMethod?: string;
  occurredAt?: string;
  relatedItemIds: string[];
  reimbursable?: boolean;
  confidence: Record<string, number>;
  sourceText: string;
}
```

- 금액·날짜가 없으면 저장 버튼을 비활성화한다.
- 낮은 신뢰도 필드는 강조하고 사용자가 직접 선택한다.
- AI가 분류를 실패해도 직접 입력 폼으로 계속할 수 있다.
- 원문 문장과 확정 비용 데이터를 분리한다.

### 4.2 비용 API

```text
POST   /api/expenses/parse
POST   /api/expenses
PATCH  /api/expenses/:itemId
DELETE /api/expenses/:itemId
GET    /api/expenses/summary?from=&to=&currency=
GET    /api/expenses/recent
```

생성은 `unified_items(item_type=expense)`와 `expense_entries`를 한 서버 트랜잭션으로 처리한다. 영수증 연결은 `content_assets`와 `attachment_of` 관계를 사용한다.

### 4.3 비용 요약

빠른 추가 비용 모드 하단에 작은 요약만 표시한다.

```text
이번 달 328,000원 · 예산 47%
미처리 영수증 2건                     [자세히]
```

- 서로 다른 통화를 환율로 임의 합산하지 않는다.
- 환산값을 제공할 때 기준일·환율 출처·원금액을 함께 표시한다.
- 기존 환율·금리 위젯은 조회 도구로 유지하고 비용 정본으로 사용하지 않는다.

## 5. 음성 입력

### 5.1 두 가지 동작

1. **음성으로 텍스트 입력**
   - 짧게 말한 내용을 현재 입력창의 초안으로 변환한다.
   - 원본 오디오는 전사 후 폐기한다.
2. **음성메모**
   - 녹음 재생·전사·요약을 제공한다.
   - 사용자가 `원본도 보관`을 선택한 경우만 비공개 자산으로 저장한다.

### 5.2 브라우저 캡처

```text
navigator.mediaDevices.getUserMedia({ audio: true })
  → MediaRecorder 지원 MIME 탐색
  → 녹음 조각 임시 IndexedDB
  → 완료 시 Blob 생성
  → 전사 API
  → 폐기 또는 사용자 선택 보관
```

- HTTPS와 사용자 제스처 안에서만 권한을 요청한다.
- MIME을 고정하지 않고 `MediaRecorder.isTypeSupported()`로 선택한다.
- 마이크 권한을 페이지 진입과 동시에 요청하지 않는다.
- 인앱 브라우저에서 차단되면 Safari/Chrome으로 열기 안내를 제공한다.
- 녹음 중 화면 잠금·앱 전환·전화 수신으로 트랙이 종료될 수 있음을 처리한다.
- 배포 환경의 요청 크기와 실행 시간 한도를 확인해 클라이언트 제한을 같은 값 이하로 둔다.

### 5.3 전사 API

```text
POST /api/voice/transcribe
Content-Type: multipart/form-data

audio: File
mode: dictation | voice_memo | meeting
retainOriginal: boolean
targetMode: task | note | expense
```

응답:

```ts
interface TranscriptionResponse {
  transcript: string;
  artifactId: string;
  assetId?: string;
  provider: "local" | "gemini";
  retained: boolean;
  warnings: string[];
}
```

정책:

- 세션 사용자와 `aiPolicy`를 먼저 검사한다.
- `local_only`는 로컬 전사 공급자가 없으면 클라우드 전송 대신 안내한다.
- Gemini 전송 시 오디오가 외부 AI로 전송된다는 사실을 UI에 표시한다.
- 전사 실패 시 임시 음성을 즉시 지우지 않고 사용자가 재시도·다운로드·삭제를 선택하게 한다.
- 성공했고 `retainOriginal=false`면 서버 임시 파일과 클라이언트 조각을 모두 삭제한다.

### 5.4 공급자 전략

- 공통 capability에 `audio_transcription`을 추가한다.
- 로컬 PC에서는 지원되는 로컬 전사 공급자를 우선할 수 있다.
- 모바일·Vercel에서는 사용자가 허용한 Gemini 전사를 사용한다.
- 공급자 없음/실패 시 녹음 자체를 업무로 잘못 저장하지 않고 텍스트 직접 입력으로 복귀한다.
- 브라우저 Web Speech API는 지원 편차가 커서 v1 정본 경로가 아니라 선택적 실시간 미리보기로만 사용한다.

## 6. 회의 음성 처리

```text
음성 asset
  → transcription artifact
  → meeting item
  → 사용자 맥락 입력·화자 보정
  → summary artifact
  → task_extract artifact
  → 사용자 확인
  → 확정 task + contains_task/derived_from 관계
```

- 전사 원문과 요약을 같은 텍스트로 덮어쓰지 않는다.
- 참석자·담당자 추론은 후보로만 표시한다.
- 긴 회의는 클라이언트 분할 업로드 또는 비동기 작업이 준비되기 전 지원 범위를 제한한다.
- 전사 중 페이지를 닫아도 원본 보관 정책과 처리 상태를 복구할 수 있어야 한다.

### 6.1 AI 정리 전 사용자 맥락 입력

전사가 끝났다고 바로 최종 요약을 요청하지 않는다. 먼저 사용자가 전사 결과와 최소 맥락을
보정한 뒤 명시적으로 `AI로 회의록 정리`를 실행한다.

필수·선택 입력:

| 정보 | 필수 여부 | 용도 |
|---|---|---|
| 회의 주제·제목 | 필수 | 요약의 기준과 문서 제목 결정 |
| 회의 목적 | 선택 | 의사결정 회의, 진행 공유, 브레인스토밍 등 정리 관점 지정 |
| 화자 구분 | 필수 | 전사에서 탐지한 `A`, `B`, `C`를 유지하거나 이름·역할로 보정 |
| 참석자 이름·역할·소속 | 선택 | 담당자 후보와 발언 맥락 보강 |
| 안건·핵심 질문 | 선택 | 주제별 요약과 미해결 질문 추출 |
| 참고자료 | 선택 | 사용자가 직접 선택한 Drive 문서·메모·텍스트만 근거로 사용 |
| 고유명사·약어 | 선택 | 회사명, 프로젝트명, 제품명 등의 전사 오탈자 보정 |
| 결과 형식 | 선택 | 기본 회의록, 경영진 요약, 결정사항 중심, 할 일 중심 |

화자 보정 화면은 각 화자의 대표 발언과 시간 구간을 함께 보여준다. 사용자가 이름을 입력하지
않으면 `화자 A`, `화자 B`, `화자 C`를 그대로 유지하며 AI가 실제 이름을 추측해서 채우지 않는다.
화자와 담당자 연결도 확정값이 아니라 사용자 검토가 필요한 후보로 반환한다.

### 6.2 참고자료 선택 원칙

- Google Drive 전체를 검색하거나 자동으로 읽지 않는다.
- 사용자가 Google Picker 또는 앱 내 선택기로 지정한 파일만 읽는다.
- 참고자료마다 파일명, Drive 파일 ID, 선택 시각과 분석에 사용한 구간을 `manifest.json`에 기록한다.
- 대용량 자료는 전체 원문 대신 관련 구간을 추출하고 출처 페이지·시트·문단을 유지한다.
- 참고자료 원문은 Supabase에 복제하지 않고 개인 Google Drive에 둔다.
- 참고자료를 Gemini에 보낼 때는 파일 목록과 실제 전송 범위를 분석 실행 전에 표시한다.

### 6.3 AI 분석 요청 계약

최종 정리 요청에는 다음 정보만 포함한다.

```ts
interface MeetingAnalysisContext {
  meetingId: string;
  topic: string;
  purpose?: string;
  agenda?: string[];
  speakers: Array<{
    label: string;       // A, B, C
    displayName?: string;
    role?: string;
    organization?: string;
  }>;
  glossary?: string[];
  referenceExcerpts?: Array<{
    fileId: string;
    fileName: string;
    locator?: string;    // 페이지, 시트, 문단 등
    text: string;
  }>;
  transcriptChunks: Array<{
    chunkId: string;
    startedAtSeconds: number;
    endedAtSeconds: number;
    text: string;
  }>;
  outputPreset: "standard" | "executive" | "decisions" | "actions";
}
```

AI 결과는 자유 텍스트 하나가 아니라 다음 구조로 받는다.

- 회의 개요와 주제별 요약
- 확정된 결정사항과 근거 시간 구간
- 할 일 후보, 담당자 후보, 기한 후보
- 미해결 질문과 추가 확인이 필요한 내용
- 참고자료와 발언이 충돌하는 부분
- 전사·화자·고유명사가 불확실한 부분

근거가 없으면 담당자나 기한을 만들어내지 않고 `미정`으로 반환한다. AI 결과는 사용자가 검토한
후에만 최종 회의록과 업무로 확정하며, 확정 전에는 기존 업무 통계에 포함하지 않는다.

### 6.4 분석 직전 확인

`AI로 회의록 정리` 버튼을 누르기 전에 다음 항목을 한 화면에서 확인한다.

- Gemini로 전송되는 음성 또는 전사 구간
- 회의 주제, 화자 매핑, 참석자 정보
- 선택한 참고자료와 실제 발췌 범위
- 무료 Gemini 정책에 따른 제품 개선 사용 가능성
- 분석 결과의 개인 Google Drive 저장 위치

사용자가 확인하지 않으면 최종 AI 분석 요청을 보내지 않는다. 전사만 저장하고 나중에 맥락을
보완해 분석을 재개할 수 있어야 한다.

## 7. 기존 기능 보호 주의사항

- 기본 선택 모드는 기존과 동일한 `업무`로 유지한다.
- Enter 키, 추가 버튼, 업무 생성 결과와 토스트 동작을 바꾸지 않는다.
- 기존 메모·회의록 붙여넣기의 원문 추출, Drive 백업, IndexedDB 옵션을 새 UI에서도 유지한다.
- 빠른 추가 메뉴를 바꿀 때 AI 바리스타 입력창과 Calendar 명령 입력을 이동하지 않는다.
- 비용 항목이 기존 `activeCount`, 완료 건수, 오늘의 업무 지침에 업무로 잘못 계산되지 않도록 `itemType` 필터를 적용한다.
- 음성 전사 실패가 작성 중인 텍스트 초안을 지우지 않는다.
- 마이크 권한 거부가 사이트 전체 오류나 반복 권한 팝업으로 이어지지 않게 한다.
- 기존 Google 로그인·연동 scope를 음성 기능 때문에 확대하지 않는다.
- 비용 삭제가 연결된 회의·프로젝트·영수증 원본을 자동 삭제하지 않는다.
- 음성 원본 삭제와 전사 텍스트 삭제를 별도 정책으로 처리한다.
- 환율 위젯의 통계 값을 비용 저장 금액에 자동 반영하지 않는다.

## 9. 구현 순서

## 11. 중단 조건

- 사용자 확인 전에 비용·업무가 저장됨
- 원본 보관 OFF인데 Storage 또는 로그에 음성이 남음
- 비용이 기존 업무 수·완료 통계에 섞임
- 마이크 권한이 페이지 로드만으로 요청됨
- 녹음 실패 시 기존 텍스트 초안이 사라짐
- 메모·문서 업로드 또는 AI 바리스타 기존 경로가 동작하지 않음
- 다른 사용자 영수증·음성에 접근 가능
- 주제·화자·참고자료 전송 범위를 확인하기 전에 최종 AI 분석이 시작됨
- 사용자가 선택하지 않은 Drive 파일을 회의 참고자료로 읽거나 Gemini에 전송함
- 근거 없는 참석자 이름·담당자·기한을 확정값으로 저장함
