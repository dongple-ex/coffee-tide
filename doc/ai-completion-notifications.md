# AI 작업 완료 알림

바리스타 대화·업무 요청과 서버 캔버스 변환은 작업 ID를 먼저 접수하고, 화면 연결과 별도로 실행한 뒤 결과를 저장한다. 요청 당시 이 브라우저에 등록된 푸시 구독이 있으면 완료·실패 알림을 보낸다. 알림에는 질문·답변 원문을 넣지 않는다. 브라우저 내부 로컬 AI와 자동 바리스타 잡담은 대상이 아니다.

알림의 `/?aiJob=...` 링크는 로그인 후 해당 결과를 연다. 대화 답변과 승인 대기 초안은 대화로 복원할 수 있다. 캔버스는 원래 문서를 덮어쓰지 않고 결과 사본으로 열며, 추출된 할 일은 체크리스트로 보존한다. 알림을 누르지 않아도 동일 브라우저로 돌아오면 미확인 작업을 조회할 수 있다. 결과 보관 기간은 요청 후 24시간이다.

## 서버 구성

- 기존 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`를 사용한다. 공개 키는 클라이언트 빌드 때 포함되어야 한다.
- Vercel에서는 `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` 또는 `KV_REST_API_URL` / `KV_REST_API_TOKEN`이 필요하다. 없으면 작업을 접수하지 않는다.
- 단일 인스턴스 셀프호스팅은 `data/ai-jobs` 파일 저장소를 사용한다. 지속 가능한 쓰기 볼륨이 필요하며, 여러 인스턴스에서는 Redis를 사용한다.
- 요청 ID를 원자적으로 선점하여 중복 실행을 방지하고, 결과 API는 로그인 사용자와 작업 소유자를 대조한다. 푸시 구독 선택은 기존 구독 API의 비밀 endpoint capability 방식을 유지한다.
- Next.js `after`를 지원하는 배포 환경이 필요하다. 라우트 `maxDuration`은 300초이고 처리 제한은 240초다. 이는 모바일 연결 종료와 작업 실행을 분리하는 기능이며, 서버 재시작 후 자동 재실행하는 영구 작업 큐는 아니다. 인스턴스 강제 종료·플랫폼의 더 짧은 실행 제한이 발생하면 복귀 시 시간 초과를 표시한다. 외부 작업을 중복 실행할 수 있으므로 자동 재제출하지 않는다.
- 결과 저장 후 알림을 보내며, 일시적 푸시 실패는 한 번 재시도한다. 푸시 전달은 기기 네트워크·집중 모드에 따라 지연될 수 있고, 발송 성공은 실제 기기 표시 확인과 다르다.

## 모바일 확인

1. 설정에서 알림을 켜고 테스트 발송을 확인한다. 아이폰은 iOS 16.4 이상에서 홈 화면에 추가한 웹 앱으로 열어 권한을 허용한다.
2. 서버 AI 요청을 보낸 후 다른 앱으로 전환하거나 화면을 잠근다. 완료 알림을 누르면 저장된 답변이 열리는지 확인한다.
3. 처리 중 페이지를 새로고침한 뒤 미확인 결과가 복원되는지 확인한다. 캔버스 변환도 동일하게 확인한다.
4. 알림을 끈 상태에서도 결과는 저장되는지, 실패·대체 응답이 성공적인 AI 생성으로 표시되지 않는지 확인한다.
5. 다른 로그인 사용자로 결과 URL을 열면 조회가 거부되는지 확인한다.

배포 설정 변경이나 실기기 푸시 수신 검증은 로컬 자동 테스트와 별도로 수행한다.
