# CoffeeTide 데스크톱 바리스타 (Windows)

> 문서 갱신: 2026-10-02, 웹 릴리스 v1.2.8 · 데스크톱 소스 v0.1.2 · Windows 배포 ZIP v0.1.1. 아래 직접 대화창·계정 표시·모델 목록 조회는 데스크톱 소스 v0.1.2 기능으로 기존 ZIP에는 포함되지 않습니다. 웹 모델 목록 자동 조회에는 새 소스로 실행한 앱이 필요합니다. 웹 미니카드와의 차이는 [doc/20-desktop-barista-mini-card.md](../doc/20-desktop-barista-mini-card.md), CLI 연결과 검증은 [22 구현서](../doc/22-terminal-ai-connector-implementation.md)를 참조하세요.

투명 배경·테두리 없는 별도 창으로 캐릭터를 다른 앱 위에 표시합니다.
캐릭터를 드래그해 이동하고, 빈 배경은 아래 앱을 클릭할 수 있습니다.

## 실행

패키징된 `dist/CoffeeTideBarista-win32-x64/CoffeeTideBarista.exe`를 실행합니다.
**같은 폴더의 나머지 파일도 필요합니다.** 폴더 전체를 함께 옮겨 주세요.

소스에서 실행할 때는 프로젝트 루트에서 Node.js 22.12 이상으로:

```powershell
npm run desktop:install
npm run desktop:start
```

모델 목록 조회에는 데스크톱 전용 Claude Agent SDK를 사용합니다. `desktop:install`은 선택적 SDK 바이너리를 생략하고 PC에 설치된 CLI를 사용합니다. 웹 서버에 SDK를 설치하거나 CLI 인증 토큰을 복사하지 않습니다.

`npm --prefix desktop run smoke -- --smoke-models`는 별도 테스트 프로필에서 샘플 모델 메뉴를 검사한 뒤, 실제 설치된 두 CLI의 모델 목록을 질문 없이 조회합니다. 기본 `smoke`의 모델 메뉴 검사는 샘플만 사용합니다.

## 웹과 연결

1. CoffeeTide 웹을 엽니다. 패키징 앱의 기본 주소는 `https://coffee-tide.dongple.kr`, 소스 실행은 `http://localhost:3000`입니다.
2. 웹 설정 → AI·자동화 → 실험실에서 데스크톱 바리스타를 켜고 **데스크톱 바리스타 연결**을 누릅니다.
3. 캐릭터 말풍선에 표시된 6자리 코드를 입력합니다.
4. 브라우저가 로컬 네트워크 접근 권한을 물으면 허용합니다.

웹의 현재 바리스타 이름·색상·기본 사진·말풍선이 전달됩니다.
웹을 새로고침하거나 닫았다가 열면 다시 연결해야 합니다.
연결이 2분 이상 끊기면 말풍선과 연결 정보를 비웁니다.
자동화된 렌더링 검사의 메시지는 **샘플 데이터**이며 외부 서비스 연동 결과가 아닙니다.

## 설정과 조작

- 캐릭터 오른쪽 아래 **💬 대화** 버튼을 누르면 입력창이 열립니다. 평소에는 280×280, 대화할 때만 320×440이며 접어도 답변을 계속 받습니다. 답변 도착 시 버튼에 작은 표시가 남습니다.
- **대화 / 업무** 선택, 질문 입력, **커피 / 응원 / 오늘 할 일** 빠른 질문을 지원합니다. Enter로 전송하고 Shift+Enter로 줄바꿈합니다. 한글 조합 중 Enter는 전송하지 않습니다.
- 연결된 웹에서 선택한 기본 AI 또는 Claude Code/Codex CLI와 현재 캐릭터를 사용합니다. 웹 탭을 열고 연결을 유지해야 합니다. 기본 AI의 업무 처리는 기존 웹 흐름을 따르며 승인이 필요한 요청은 웹에서 확인합니다. CLI는 대화·업무 조언 범위입니다.
- 대화는 최근 10문답을 앱 메모리에만 표시하고, 다음 질문에는 완료된 최근 4문답을 길이 제한 후 전달합니다. 연결 해제·재페어링·캐릭터/AI 공급자 변경 시 지웁니다. 앱 재시작 후에는 남지 않습니다.
- 캐릭터 아래 **⚙ 설정** → **① 아이스커피 아이콘 / ② 현재 바리스타 사진** 선택.
- 최신 소스의 **⚙ 설정 → 터미널 AI 연결**에는 웹에서 선택한 CLI의 로그인 계정·요금제·계정 조회 시각·최근 응답 성공 시각과 **사용량 보기**가 표시됩니다. 창은 280×280을 유지하며 설정 내용은 내부에서 스크롤합니다.
- 같은 설정에서 CLI가 반환한 **모델 목록 → 모델 저장**을 사용할 수 있습니다. **목록 새로고침**, **자동 선택**, **모델 이름 직접 입력**도 제공합니다. 목록 조회는 질문을 보내지 않으며, 목록에 없는 저장 모델도 임의로 변경하지 않습니다. 조회된 목록은 실행 권한이나 잔여 한도 확인 결과가 아닙니다.
- 외형 선택과 창 위치는 다음 실행에도 유지됩니다.
- 사진 캐릭터는 86px 크기입니다. 말풍선은 최대 3줄로 표시하고, 긴 내용은 마우스를 올려 확인합니다.
- 캐릭터를 드래그해 이동합니다.
- ☕ 버튼은 짧은 기본 대사를 표시합니다. ↗ 버튼은 연결된 웹 탭의 대화창으로 전환합니다. 연결이 없을 때만 웹페이지를 엽니다.
- 브라우저가 창 포커스를 제한하면 자동으로 맨 앞으로 오지 않을 수 있습니다. 기존 CoffeeTide 탭을 선택하면 대화창 전환이 반영됩니다.
- − 버튼으로 숨기고 Windows 알림 영역(트레이)을 더블클릭해 다시 표시합니다.
- **왼쪽 Shift를 빠르게 두 번 눌렀다 떼기**로 다른 앱에서도 바리스타를 표시하고 CoffeeTide 대화창 열기를 요청합니다. 각 누름은 250ms 이내, 두 번의 뗀 시점 간격은 70~500ms입니다. 오른쪽 Shift, 길게 누르기, 다른 키와의 조합은 제외합니다.
- 데스크톱 앱이 실행 중이어야 하며 트레이 메뉴의 **왼쪽 Shift 두 번 · 호출 준비됨**으로 준비 상태를 확인할 수 있습니다. 연결된 웹 탭을 재사용하고, 연결이 없을 때만 웹페이지를 엽니다. 웹만 실행 중이면 CoffeeTide 창에 포커스가 있을 때 작동합니다.
- 트레이 우클릭 메뉴에서 외형 변경, 연결 초기화, 위치 복원, 종료가 가능합니다.

## 다른 웹 주소

보조 앱을 모두 종료한 뒤, 정확한 웹 주소로 실행합니다.

```powershell
$env:COFFEETIDE_URL = 'https://your-coffeetide.example'
npm run desktop:start
```

지정한 주소는 기본 웹 origin과 미연결 시 열 주소입니다. 최초 페어링은 이 origin 외에 localhost/127.0.0.1, `.vercel.app`으로 끝나는 origin, `https://coffee-tide.dongple.kr`도 허용합니다. 페어링 후에는 토큰과 연결한 정확한 origin을 모두 검증합니다. 최초 페어링의 허용 정책 축소는 백로그 M2의 검토 항목입니다. 사용자 설정 주소는 로컬 HTTP 또는 HTTPS여야 합니다.
배포된 HTTPS 사이트에서의 연결은 브라우저의 로컬 네트워크 정책에도 영향을 받으므로 별도 환경 검증이 필요합니다.

## 로컬 데이터와 보안

- 통신 서버는 `127.0.0.1:47381`에만 열립니다.
- 화면의 일회용 연결 코드와 메모리에만 보관하는 토큰으로 인증합니다.
- 웹 계정 토큰, API 키, 대화 이력을 데스크톱 앱에 저장하지 않습니다.
- 저장 파일에는 외형 선택·창 위치와 터미널 AI의 실행 경로·작업 폴더·모델 설정이 들어갑니다.
- 캐릭터 이미지는 앱에 포함된 파일만 사용합니다.
- Windows 자동 시작 등록은 수행하지 않습니다.
- 전역 단축키는 숨겨진 Windows PowerShell 프로세스에서 C# 키보드 훅을 실행합니다. 키 입력은 저장하거나 전송하지 않고, 완성된 호출 동작만 Electron에 알립니다. 앱 종료 또는 부모 프로세스 연결 종료 시 감지기도 종료합니다. Windows PowerShell/C# 실행을 제한하는 환경에서는 단축키 사용 불가 상태를 표시합니다.

## Claude Code / Codex CLI 대화 연결

별도 LLM 서버 없이 이 PC의 CLI를 통해 제공업체의 클라우드 모델과 대화합니다. 구현·권한·검증 상세는 [터미널 AI 연결 구현서](../doc/22-terminal-ai-connector-implementation.md)를 참고하세요.

1. 사용할 CLI를 설치하고 일반 터미널에서 `claude` 또는 `codex`로 로그인합니다.
2. 바리스타 v0.1.1 이상을 실행하고 웹과 페어링합니다. v0.1.0 앱에는 이 기능이 없으므로 새 다운로드 파일로 업데이트해야 합니다.
3. 웹 설정 → AI·자동화 → AI 캐릭터 → **터미널 AI 연결**에서 공급자를 선택합니다.
4. 실행 경로와 작업 폴더는 비우면 자동 탐색/앱 전용 폴더를 사용합니다. 직접 지정할 때 Windows에서는 네이티브 `.exe` 절대 경로를 사용합니다. `.cmd`/`.ps1` 명령은 실행하지 않습니다.
5. 최신 소스의 **저장·설치·계정 확인** 후 AI 바리스타 채팅이나 미니카드에서 질문합니다. 모델 이름은 선택 사항입니다. 계정 조회는 모델을 호출하지 않으며 실제 응답 성공은 질문에 답변이 돌아온 뒤 표시됩니다.
6. 채팅의 **중지** 또는 설정의 **답변 취소**로 요청을 취소합니다.

캐릭터 지침·최근 대화·질문을 전송하며 업무 데이터 전체를 자동 전송하지 않습니다. 첫 버전은 대화 송수신용이며 MCP·스킬·파일 수정 실행은 후속 범위입니다. CLI 선택 후 연결/로그인 실패 시 다른 모델로 자동 전환하지 않습니다. CLI의 기존 로그인과 계정 한도를 사용하고 인증 토큰을 CoffeeTide에 복사하지 않습니다.

```powershell
# 설치 검사만 수행 (모델 호출 없음)
node desktop/scripts/cli-ai-smoke.cjs
# 명시적으로 실제 계정에 합성 연결 확인 질문을 보냄
node desktop/scripts/cli-ai-smoke.cjs --live
```

## 검증 및 패키징

```powershell
npm run desktop:test
npm --prefix desktop run smoke
npm run desktop:package
```

`smoke-output/`에 두 외형의 PNG 및 검사 결과 JSON이 생성됩니다.
smoke는 별도 프로필과 임시 포트를 사용하며 실제 사용자 설정을 바꾸지 않습니다.
패키지는 서명되지 않은 개발 빌드입니다. 검증 PC의 Windows 앱 제어 정책에서 배포 EXE 실행을 차단해 패키지 자체의 실행 검증은 미완료입니다. 개발용 Electron 스모크와 패키지 소스·버전·네이티브 파일 대조는 통과했습니다.

Windows v0.1.1 배포 ZIP은 GitHub Release `barista-v0.1.1`에 보관합니다. 웹의 `/download/CoffeeTideBarista.zip`은 해당 릴리스의 파일로 임시 리다이렉트하며, ZIP 자체는 Git/Vercel 소스에 포함하지 않습니다.

PowerShell에서 읽는 `native/` 스크립트는 `app.asar.unpacked/native/`에 배치합니다. ASAR 내부 가상 경로를 외부 프로세스에 넘기지 않습니다.


### 연결된 웹 미니카드의 본체 최소화 (Windows)

최신 보조 앱과 6자리 코드로 연결한 경우에만, 웹 미니카드를 열면 Chrome/Edge의 CoffeeTide 본체 창을 최소화합니다. 임시 제목 식별값과 브라우저 프로세스를 확인해 일치하는 창이 하나일 때만 제어합니다. 다른 창을 제목 일부로 추측해 최소화하지 않습니다.

왼쪽 Shift 두 번으로 본체를 복원하고 웹 미니카드를 닫습니다. 대화와 입력 중인 질문은 유지됩니다. `_` 접기는 미니카드 내용만 접습니다. 연결 해제·정상 종료 시 본체 복원을 시도합니다. 강제 프로세스 종료나 브라우저 제목 변경 등으로 자동 복원이 실패하면 작업 표시줄에서 본체를 직접 복원할 수 있습니다.

웹 코드와 보조 앱을 함께 업데이트하고 보조 앱을 재시작한 뒤 다시 연결해야 합니다. 미연결 상태, 이전 보조 앱, Windows 이외의 환경에서는 자동 최소화를 요청하지 않습니다.
